# Онлайн-запись на уроки

Сервис записи на занятия с подтверждением заявок. Преподаватель сам открывает свободное время, ученики выбирают удобные слоты в календаре и отправляет заявку, а преподаватель одобряет или отклоняет её на сайте или прямо в Telegram.

**Сайт:** https://eclipsseii.github.io/lesson-booking/

## Что умеет

**Для ученика**
- календарь, в котором можно выбрать только дни со свободным временем;
- свободные окошки по 30 минут, занятые просто не показываются;
- анкета при записи: имя, учитель в школе, комментарий;
- защита от повторной записи: один человек может записаться только раз в день.

**Для преподавателя (админка)**
- вход по почте и паролю;
- заявки сгруппированы: новые сверху, дальше одобренные и отклонённые;
- календарь на месяц: видно, в какие дни открыты окошки и есть записи;
- окошки разделены с 8:00 до 22:00 по пол часа, включаются и выключаются переключателем;
- расписание дня с именами, учителем и комментарием;
- отмена записи, после неё окошко снова становится свободным.

**Telegram-бот**
- присылает каждую новую заявку с кнопками «Одобрить» и «Отклонить»;
- после нажатия сообщение обновляется(добавляется статус);
- команды `/pending`, `/today`, `/tomorrow`, `/week` показывают заявки и расписание.

## Стек

- **Фронтенд:** HTML, CSS, JavaScript без фреймворков, вёрстка под телефон
- **База данных:** Supabase (PostgreSQL)
- **Бэкенд бота:** Supabase Edge Functions (Deno, TypeScript), Telegram Bot API
- **Хостинг:** GitHub Pages

## Как устроено

В базе три таблицы:

| Таблица | Что хранит |
|---|---|
| `open_slots` | окошки, которые открыл преподаватель |
| `requests` | заявки учеников и их статус: ждёт, одобрена, отклонена |
| `tg_messages` | какое сообщение в Telegram относится к какой заявке |

Посетители сайта не читают таблицы напрямую. Доступ закрыт правилами **Row Level Security**, и ученикам открыты только две функции на SQL:

- `get_free_slots` — свободные окошки за период, без чужих имён;
- `send_request` — сохраняет заявку и сама проверяет, что окошко открыто и не занято, дата не в прошлом, а этот человек ещё не записан на тот же день. Одно окошко нельзя занять дважды, даже если два человека нажмут «Отправить» одновременно: это гарантирует уникальный индекс в базе.

Читать и менять таблицы может только вошедший администратор.

Когда в `requests` появляется новая строка, триггер в базе через `pg_net` вызывает Edge Function. Функция отправляет сообщение в Telegram. Нажатия на кнопки приходят в ту же функцию через вебхук, она меняет статус заявки в базе и обновляет сообщения. Запросы от базы и от Telegram функция проверяет по секретному ключу.
